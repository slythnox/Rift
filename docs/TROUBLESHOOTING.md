# Troubleshooting Guide

This guide describes common build, runtime, and network challenges encountered during the development and execution of Rift, accompanied by reproducible resolutions.

---

## 1. Build and Compilation Issues

### Gradle Daemon Heap Exhaustion (`OutOfMemoryError`)
- **Symptoms:** The build halts during `compileArm64FossDebugKotlin` with `java.lang.OutOfMemoryError: Java heap space`.
- **Remedy:**
  - Execute Gradle commands with the `--no-daemon` parameter.
  - Confirm `gradle.properties` allocates adequate memory:
    ```properties
    org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m
    ```

### KSP / Room Schema Stale Compilation
- **Symptoms:** Room symbol errors or missing DAO implementations following Git branch switches.
- **Remedy:** Clean existing generated sources and assemble cleanly:
  ```powershell
  .\gradlew.bat --no-daemon :app:clean :app:assembleArm64FossDebug
  ```

## 2. Audio Streaming and Network Challenges

### HTTP 403 Forbidden / Stream Expiration
- **Symptoms:** Playback stalls with an ExoPlayer `HttpDataSource$InvalidResponseCodeException` reporting HTTP 403.
- **Root Cause:** YouTube streaming URLs generated by InnerTube carry timed authentication signatures (`expire` timestamps) that eventually lapse.
- **Remedy:**
  - Rift automatically purges stale URLs after 4 hours or upon an unrecoverable HTTP 403 event, issuing a fresh InnerTube resolution.
  - Check that network connectivity is stable and that IP address throttling by YouTube is not active. If necessary, configure a proxy within `Settings > Content > Proxy`.

### Spotify Playlist Import Returns No Tracks
- **Symptoms:** The import dialogue displays "0 tracks imported" or fails immediately.
- **Root Cause:** The provided Spotify playlist is either private, collaborative-restricted, or dynamic (such as "Liked Songs" or algorithmic "Made For You" mixes).
- **Remedy:**
  - Verify that the target playlist is configured as **Public** within Spotify.
  - Ensure the URL matches the canonical syntax: `https://open.spotify.com/playlist/{id}`.

## 3. Runtime and Device Specifics

### Playback Notifications Absent on Android 13+ (API 33+)
- **Symptoms:** The ongoing media player controls do not appear in the system notification shade or lock screen.
- **Remedy:** Ensure the `POST_NOTIFICATIONS` runtime permission has been granted under system `Settings > Apps > Rift > Notifications`.

### Liquid Glass Rendering Stutter on Older Hardware
- **Symptoms:** Frame rate dips or UI stutter during list scrolling on devices without hardware-accelerated RenderEffect support.
- **Remedy:** Disable real-time backdrop blur under `Settings > Appearance > Liquid Glass` to utilise flat, solid Material 3 surface containers.

### Random Playback Stops Mid-Track
- **Symptoms:** A song unexpectedly stops playing without user interaction, without displaying an error, or during network transitions between Wi-Fi and Cellular.
- **Root Causes:**
  1. *Buffering State Intent Drop:* In Media3, player.isPlaying evaluates to false during STATE_BUFFERING. Dynamic network-quality or IP reloads checking only isPlaying skipped invoking player.play().
  2. *AudioTrack Corruptions:* handleAudioRendererError paused the player to reset the sink, but checked only wasPlayingBeforeAudioFocusLoss before resuming, which was false during normal playback.
  3. *External Stream 10MB Subranges:* Non-YouTube providers (JioSaavn, HTTP add-on streams) were partitioned into 10MB chunks, causing unexpected EOF on static audio servers.
  4. *HTTP 410 Gone Expirations:* YouTube signed URLs returning HTTP 410 were not treated as expired stream URLs, falling through to generic unrecoverable failure paths.
- **Remedies & Diagnostics:**
  - Rift preserves player.playWhenReady || player.isPlaying across all dynamic reloads, audio focus transient states, AudioTrack resets, and recovery routines.
  - External stream providers are delivered in open-ended requests without subrange truncation.
  - HTTP 410 and 403 are categorized as expired URLs for automatic stream refresh.
  - In-memory event traces can be queried via PlaybackDiagnostics.getRecentEvents() to verify recent lifecycle transitions and error codes.

### Speed Dial Random Discovery Queues Familiar Songs or Fails to Start
- **Symptoms:** Tapping the 5-dot Random button does not start playback or seems to queue familiar tracks.
- **Root Cause:** If the local Room database has empty recent listening history (e.g. brand-new installation or recently cleared history), the generator cannot sample from recent events.
- **Remedy:**
  - Rift automatically falls back sequentially to liked songs, library favorites, and quick picks when recent history is sparse.
  - As you listen to a few songs, database.recentEvents() populates, enabling full anti-fatigue filtering and discovery matching.

### Songs Excluded From Autoplay or Radio Continuations
- **Symptoms:** A specific song or artist never appears in upcoming autoplay queues or radio recommendations.
- **Root Cause:** The song (or a cross-provider canonical equivalent) was previously marked as Disliked.
- **Remedy:**
  - Navigate to Settings > Disliked Songs to inspect all currently disliked entries.
  - Tap the restore / thumb-up button on any track to un-dislike it and immediately restore its eligibility for recommendation algorithms.

### Adaptive Session Intelligence (ASI) Fallback
- **Symptoms:** Recommendations behave identically to baseline auto-mix despite ASI being enabled.
- **Root Cause:** If multi-source candidate generation exceeds its 1.5s sub-timeout or overall recommendation generation exceeds 2.0s (e.g. during extreme network congestion), ASI safely returns null.
- **Remedy:**
  - MusicService automatically falls back to RecommendationPostProcessor without halting playback or dropping frames. Check ASIDiagnostics in-memory logs for timeout details.
